# SCL-506/SCL-507 Catálogo de upsells + Pedido integrado ao Financeiro — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Catálogo de produtos pós-ensaio administrável, ofertas por galeria, pedido feito pela cliente no portal (preço calculado no servidor, idempotente) e acompanhado pela equipe, com cobrança pelo Payment existente.

**Architecture:** Migration 0052 cria `upsell_order_status`, `upsell_products`, `gallery_upsell_offers`, `upsell_orders`, `upsell_order_items`, `payments.upsell_order_id` (FK composta com o Shoot), trigger `upsell_orders_consistent`, recria `payments_client_read` sem upsell e RLS staff-only. `domain/upsell` concentra Zod, regras puras e serviços auditados; o portal usa Server Action própria (sessão → cliente) e o Admin usa `defineAdminAction`. Os leitores de saldo do ensaio passam a ignorar `upsell_order_id`.

**Tech Stack:** Next.js 16 App Router (Server Actions), Drizzle ORM, Zod 4, Vitest + Testing Library, Tailwind.

**Spec:** `docs/superpowers/specs/2026-09-26-scl506-scl507-upsell-design.md`

## Global Constraints

- Única migration da leva: `0052`, `prevId` = id do snapshot 0051; `when` real e monotônico; migrations anteriores intocadas.
- drizzle-kit não roda neste ambiente: SQL, snapshot e journal escritos à mão no formato exato do gerador.
- Nenhuma dependência nova. Nada conecta ao banco em import.
- `actorUserId` vem de `ctx.user.id` (Admin) ou do contexto do portal (cliente); preço/total nunca vêm do browser.
